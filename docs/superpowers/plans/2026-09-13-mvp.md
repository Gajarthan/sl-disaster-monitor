# Sri Lanka Disaster Monitor implementation plan

Goal: independently collect DMC documents, preserve source provenance, publish historical Parquet to Hugging Face and serve a static GitHub Pages dashboard.

Architecture: scheduled Python collection with bounded downloads, SHA-256 identity, conservative deterministic extraction and explicit failure states. Small current/recent JSON feeds are derived from yearly Parquet archives; Hugging Face holds a public mirror. Plain JavaScript and locally vendored Leaflet render district geometry without a tile service.

The user's detailed architecture and definition of done are the implementation specification. Public owners: Gajarthan (GitHub), gajarthan (Hugging Face).

- [x] Stage 1: fixture tests for listing parsing, Unicode language classification, multilingual districts, hazard/severity rules, invalid PDFs, deduplication, schema and failure recovery. Implement scraper modules and run live bounded collection twice to verify idempotency.
- [x] Stage 2: typed yearly Parquet, dataset card, upload command and dataset-server query contract. Verify roundtrip and public publishing.
- [x] Stage 3: accessible static dashboard with local recent search, optional historical adapter, district map, source detail and stale/failure indicators. Test filters and inspect rendered desktop/mobile UI.
- [x] Stage 4: scheduled scraping, publication and Pages workflows, CI, setup documentation, attribution and separate software/data licensing. Verify hosted dashboard and workflow execution.

Data contract: alerts are arrays with id/source/document_type/hazard/hazards/severity/title/description/summary/language/language_confidence/language_reason/issued_at/valid_from/valid_until/districts/provinces/source_page/source_pdf/content_hash/processed_at. `official` preserves listing title/description/date/time/category/URLs. `extraction` records rules version, status, evidence and location scope (mentions, not confirmed affected areas). Unknown validity stays null. Unknown severity stays unknown. No-text PDFs still produce source-linked records with extraction status no_text and unknown language.

Metadata includes last_run/status/last_successful_scrape/last_dmc_document_seen/documents_checked/new_documents/failed_documents/download_failures/parsing_failures/duplicate_count/unknown_language_count/category status/errors. Failed collection retains previous records and last successful timestamp. Frontend treats stale/partial/error data as incomplete, never as an all-clear.

Data strategy: archive/alerts-YYYY.parquet with explicit Arrow schema and a small manifest of URL-to-hash processing state. Only data/*.json and optimized district geometry reach Pages. Archive queries use Hugging Face filter endpoint, with scalar district membership columns to avoid unsupported list predicates.

UI direction: pale blue-gray (#edf3f7), navy (#143449), teal (#087e8b), amber (#b16a00), red (#bb3543), white. Condensed display headings, system sans body, monospace timestamps. A large tile-free Sri Lanka district map is the signature element; a readable report list and filter bar sit alongside it. A persistent independent-source notice and health strip precede the reports.

Validation commands: `python -m pytest -q`, `node --test tests/frontend.test.mjs`, `python -m scraper.pipeline --max-pages 2`, `python -m huggingface.build_dataset --validate`, `python scripts/build_site.py`.

Release verification: 138 unique live DMC records, 33 latest reports, 55 Python tests and 10 Node tests passed. GitHub tests, scheduled-workflow manual dispatch, Hugging Face publication and Pages deployments succeeded. Hosted JSON and all 25 districts verified. Hugging Face metadata, Parquet and first-row preview endpoints respond successfully; filter/rows endpoints currently return provider-busy errors, correctly surfaced without blocking local recent search.
